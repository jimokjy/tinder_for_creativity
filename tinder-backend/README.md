# Creations Feed API

Бэкенд-скелет для проекта "Тиндер для творчества": анонимная публикация
работ, случайная лента и лайки. Сделан на **FastAPI + SQLAlchemy**.

## Запуск

```bash
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env

uvicorn app.main:app --reload
```

Swagger-документация: http://localhost:8000/docs

Если хотите открыть сайт для доступа из интернета, оставаясь на своём
железе (например, через Cloudflare Tunnel) — **наружу нужно выводить
только фронтенд**. Бэкенд сам наружу не смотрит: Next.js-сервер
проксирует к нему запросы внутри одного ноутбука (`localhost`), см.
`rewrites()` в `next.config.js` фронтенда и его README. `CORS_ORIGINS`
в этом случае можно оставить как есть — браузер обращается только к
адресу фронтенда, до бэкенда напрямую не достаёт.

## Как устроена анонимность

У каждого посетителя при первом запросе генерируется UUID и кладётся
в httponly cookie `anon_session_id` (см. `app/dependencies.py`). Дальше
именно этот UUID используется:
- как автор — когда человек публикует творение;
- как зритель — когда ставит лайк или листает ленту.

Никакой регистрации, email или пароля не требуется.

## Как устроена авторизация

Простой логин/пароль — без email и подтверждений. При регистрации
пароль хэшируется через `bcrypt`, при входе выдаётся JWT-токен в
httponly cookie `access_token` (см. `app/security.py`, `app/dependencies.py`,
`app/routers/auth.py`).

Важно: **id аккаунта используется только внутри бэкенда** — чтобы автор
видел свои творения и их лайки. Наружу (в ленте, на карточках творений)
username или любые другие данные аккаунта никогда не отдаются — для
всех остальных пользователей публикации и лайки по-прежнему анонимны.

Почти все роуты (публикация, лента, лайки, свои творения) теперь
требуют авторизации — без входа в аккаунт ими нельзя пользоваться.

## Вход через ЛК Силаэдра (OpenID Connect)

Помимо обычной регистрации, доступен вход через `lk.silaeder.ru` —
см. `app/oidc_client.py`, `app/routers/oidc.py`, `app/mailer.py`.
Выключен по умолчанию (`CRM_OIDC_ENABLED=false`); чтобы включить,
заведите OIDC-клиент в ЛК Силаэдра и заполните переменные
`CRM_OIDC_*` в `.env` (см. `.env.example`).

Как это работает:
- Аккаунт для внешнего пользователя ищется по паре `(issuer, sub)`,
  а не по email — email никогда не используется для автоматической
  привязки.
- Если email из Силаэдра совпал с уже существующим локальным
  аккаунтом — привязка НЕ происходит автоматически, на этот email
  отправляется одноразовая ссылка подтверждения (30 минут,
  `app/mailer.py`; без настроенного `MAIL_HOST` ссылка просто пишется
  в лог сервера).
- Если email новый — создаётся новый аккаунт без пароля (войти в
  него можно только через Силаэдр).
- Роль (`admin` всегда становится `teacher`), имя и email
  обновляются из `userinfo` при каждом входе.
- Явная привязка к уже открытому аккаунту — `GET /auth/silaeder/link`
  (требует входа).

Redirect URI для регистрации в ЛК Силаэдра:
`{APP_URL}/auth/silaeder/callback`.

## Структура проекта

```
app/
  main.py          - точка входа, подключение роутов и статики
  config.py        - настройки (БД, папка загрузок, лимиты, JWT, OIDC)
  database.py      - подключение к БД (SQLAlchemy)
  models.py        - таблицы: User, OidcIdentity, OidcLinkToken, Creation, Like, Seen, Report
  schemas.py       - Pydantic-схемы запросов/ответов
  security.py      - хэширование паролей, JWT, auth-cookie
  dependencies.py  - авторизация текущего пользователя по cookie
  storage.py       - сохранение файлов (сейчас — локальный диск)
  oidc_client.py   - регистрация OIDC-клиента (authlib) для Силаэдра
  mailer.py        - отправка ссылки подтверждения привязки
  routers/
    auth.py        - регистрация, вход, выход, "кто я"
    oidc.py        - вход/привязка через ЛК Силаэдра
    creations.py   - публикация, свои творения, удаление, жалобы
    feed.py        - случайная лента
    likes.py       - лайк / убрать лайк
```

## Что стоит доделать перед продакшеном

0. **Схема БД снова поменялась (добавлен вход через Силаэдр)** — если у
   вас уже есть `app.db` от предыдущей версии, удалите его перед первым
   запуском (`Base.metadata.create_all` создаёт только отсутствующие
   таблицы, но не меняет структуру существующих — а `password_hash` у
   `User` стал необязательным, плюс появились новые таблицы). Это же
   правило и для более старых баз: если запускали бэкенд ещё до
   авторизации вообще, старые творения были привязаны к анонимным
   cookie-сессиям, а не к аккаунтам, и без миграции окажутся "ничьими".
1. **Миграции.** Сейчас таблицы создаются автоматически при старте
   (`Base.metadata.create_all`). Для реального проекта нужен Alembic,
   чтобы менять схему БД без потери данных.
2. **PostgreSQL вместо SQLite.** SQLite отлично подходит для разработки,
   но для продакшена и параллельных нагрузок нужен Postgres — достаточно
   поменять `DATABASE_URL`.
3. **Хранилище файлов.** Сейчас файлы лежат на локальном диске. Для
   продакшена лучше S3-совместимое хранилище (S3, Cloudflare R2,
   Yandex Object Storage) — меняется только `app/storage.py`.
4. **Модерация контента.** Есть базовый механизм жалоб с автоскрытием
   после N жалоб (`AUTO_HIDE_REPORT_THRESHOLD`), но стоит добавить и
   автоматическую проверку загружаемых файлов (например, через готовые
   сервисы модерации изображений).
5. **Рейт-лимитинг.** Чтобы один и тот же аноним не мог заспамить ленту
   сотнями публикаций подряд — добавить ограничение частоты по
   session_id/IP (например, через slowapi).
6. **Производительность случайной выборки.** `ORDER BY RANDOM()` в
   `feed.py` подходит для MVP, но на больших объёмах данных станет
   медленным — см. комментарий в коде с альтернативным подходом.
7. **HTTPS и secure-cookie.** В `dependencies.py` включить `secure=True`
   у cookie, когда сайт будет работать по HTTPS.
