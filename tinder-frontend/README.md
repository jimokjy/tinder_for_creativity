# Куча — фронтенд

Фронтенд на **Next.js 14 (App Router) + TypeScript + Tailwind + framer-motion**
для бэкенда `tinder-backend`. Реализует план: авторизация (логин/пароль),
лента со свайпом, публикация работ, свои работы со статистикой лайков.

## Экраны

0. **Вход/регистрация** (`/login`) — простой логин+пароль, без email,
   плюс кнопка входа/регистрации через ЛК Силаэдра (OpenID Connect,
   работает только если на бэкенде настроен и включён `CRM_OIDC_*` —
   см. README бэкенда). Аккаунт нужен только чтобы не терять доступ к
   своим публикациям — в ленте и лайках всё по-прежнему анонимно, логин
   нигде не светится.
1. **Лента** (`/`) — карточка случайного творения, которую можно свайпнуть
   мышью/пальцем, кликнуть кнопками ✕/♥ или пролистать стрелками ← →.
2. **Сдать работу** (`/upload`) — форма публикации (файл и/или текст).
3. **Мои приколотые** (`/mine`) — сетка своих работ со счётчиком лайков и
   возможностью удалить.

Неавторизованного пользователя `AuthGate` (см. `components/AuthGate.tsx` и
`lib/auth-context.tsx`) автоматически перекидывает на `/login`; авторизованного,
наоборот, со страницы логина уводит на ленту.

## Дизайн-концепция

Вместо шаблонных карточек на светлом фоне — метафора **доски объявлений
в мастерской**: тёмно-синий фон-стенд, творения — "приколотые" бумажные
карточки с булавкой и лёгким наклоном. Пролистывание в ленте физически
похоже на то, как отбрасывают полистанную карточку в сторону.
Форма загрузки стилизована под бланк для анонимной сдачи работы.

Шрифты: **Fraunces** (заголовки, с характером) + **Inter** (интерфейс) +
**Space Mono** (счётчики лайков, метки — как проставленный штамп).

## Запуск (локально)

```bash
npm install
cp .env.local.example .env.local
# менять .env.local обычно не нужно — бэкенд по умолчанию на localhost:8000

npm run dev
```

Откройте http://localhost:3000 — бэкенд (`tinder-backend`) должен быть
запущен рядом (порт 8000).

Браузер всегда обращается только к адресу фронтенда: запросы к `/api/*` и
`/uploads/*` сам Next.js-сервер прозрачно перенаправляет на бэкенд (см.
`rewrites()` в `next.config.js`). Поэтому не нужен ни CORS, ни отдельный
адрес API на стороне браузера — это же и упрощает открытие сайта наружу
(см. ниже).

## Как открыть сайт для друзей, оставив хостинг на своём ноутбуке

Раз браузер обращается только к одному адресу (фронтенду), достаточно
"вывести наружу" **только его** — бэкенд наружу светить не нужно вообще.

Проще и безопаснее всего — **Cloudflare Tunnel**: он создаёт зашифрованный
туннель от ноутбука до Cloudflare и даёт бесплатный HTTPS-адрес, без
проброса портов на роутере (которого часто и добиться-то нельзя — многие
провайдеры блокируют входящие соединения) и без раскрытия домашнего IP.

1. Соберите продакшен-сборку (она быстрее и стабильнее dev-режима):
   ```bash
   npm run build
   npm start          # слушает localhost:3000
   ```
2. В соседнем терминале, рядом с бэкендом (`uvicorn app.main:app`, тоже
   без `--reload` в проде), поставьте `cloudflared`:
   - Windows: `winget install --id Cloudflare.cloudflared`
   - macOS: `brew install cloudflared`
   - Linux: см. https://pkg.cloudflare.com
3. Запустите быстрый туннель на порт фронтенда:
   ```bash
   cloudflared tunnel --url http://localhost:3000
   ```
   В терминале появится ссылка вида `https://random-words.trycloudflare.com`
   — это и есть публичный адрес сайта, его можно отправить друзьям.

Нюансы такого варианта:
- Ссылка **меняется при каждом перезапуске** `cloudflared` — для
  постоянного адреса нужен свой домен и именной туннель (Cloudflare это
  тоже позволяет бесплатно, но там уже нужна регистрация домена).
- Ноутбук должен быть включён, подключён к интернету и не уходить в сон,
  пока сайт должен быть доступен (в настройках питания стоит отключить
  сон при работе от сети).
- Бэкенд наружу через туннель выводить не нужно — Next.js достаёт данные
  с него сам, по `BACKEND_URL` из `.env.local` (по умолчанию
  `http://127.0.0.1:8000`, менять не нужно, если оба сервиса на одном
  ноутбуке).
- Быстрый туннель не требует ни аккаунта Cloudflare, ни домена — это
  самый низкопороговый способ попробовать.

## Структура

```
app/
  layout.tsx        - шрифты, шапка с навигацией, AuthProvider/AuthGate
  page.tsx           - лента (свайп)
  login/page.tsx      - вход и регистрация
  upload/page.tsx    - форма публикации
  mine/page.tsx       - свои работы + лайки
  globals.css         - текстура доски, стиль "приколотой" карточки
components/
  Header.tsx          - показывает логин и кнопку "выйти"
  AuthGate.tsx        - блокирует контент, пока не проверена авторизация
  SwipeCard.tsx       - драг-карточка (framer-motion)
  CreationMedia.tsx   - рендер картинки/аудио/текста
  Tag.tsx
  EmptyState.tsx
lib/
  api.ts              - клиент к FastAPI-бэкенду (fetch, cookie-сессия)
  auth-context.tsx    - React-контекст авторизации, редиректы
  types.ts
```

## Что стоит доделать

1. **Индикатор "нет соединения с сервером"** — сейчас есть базовая
   обработка ошибок API, но не автоповтор при обрыве сети.
2. **Пагинация/кэш ленты** — сейчас каждый свайп — отдельный запрос
   `/feed/random`; для большей отзывчивости можно предзагружать
   следующую карточку заранее.
3. **Модерация на фронте** — кнопка "пожаловаться" на карточке в ленте
   (эндпоинт `/creations/{id}/report` на бэкенде уже есть, на фронте
   пока не подключена).
4. **Оптимистичный лайк** — сейчас лайк отправляется после того, как
   карточка улетает с экрана; можно показывать мгновенную обратную
   связь до ответа сервера.
5. **next/image** — сейчас картинки рендерятся через обычный `<img>`,
   т.к. домен файлов бэкенда заранее неизвестен; при деплое можно
   настроить `next/image` с конкретным доменом для оптимизации.
